🔑 Environment Files

Create these files before running anything. They are git-ignored and never committed.

apps/api/.env copy from apps/api/.env.example 
# PostgreSQL connection
DATABASE_URL="postgresql://postgres:ShipFlow@DB#2026@localhost:5432/ship_flow_dev?schema=public"

# JWT
JWT_SECRET="super_secret"

# Server
PORT=9000
NODE_ENV="development"

# CORS — must match web dev port
FRONTEND_URL="http://localhost:9001"
apps/web/.env copy from "apps/web/.env example" 
NEXT_PUBLIC_API_URL="http://localhost:9000"
NEXT_PUBLIC_API_BASE_URL="http://localhost:9000"
packages/database/.env Prisma CLI reads this directly 
# Must match DATABASE_URL in apps/api/.env
DATABASE_URL="postgresql://postgres:ShipFlow@DB#2026@localhost:5432/ship_flow_dev?schema=public"
packages/api-tests/.env.test Integration test credentials 
API_BASE_URL=http://localhost:9000
TEST_EMAIL=test+org@shipflow.dev
TEST_PASSWORD=Test@1234
ℹ️ DATABASE_URL must be identical in apps/api/.env and packages/database/.env. The API uses it at runtime; Prisma CLI uses it during migrations.

🚀 First-Time Setup

Run these once after cloning the repo, in order.

  • 1
    Install all dependencies pnpm workspaces installs everything for all packages at once. 
pnpm install
  • 2
    Build shared packages Apps import compiled types — build database and shared first. 
pnpm --filter @shipflow/database build
pnpm --filter @shipflow/shared build
  • 3
    Run the initial migration Creates all database tables and generates the Prisma client. 
pnpm db:migrate:dev
  • 4
    Generate Prisma client Only needed if migrate:dev wasn't run or client is stale. 
pnpm db:generate
  • 5
    (Optional) Seed the database Inserts initial test data via packages/database/src/seed.ts. 
pnpm db:seed

🗄️ Database Scripts — Order Matters

All root-level db:* scripts delegate to packages/database.

Order Root Script What it does When to run Env
1 pnpm db:migrate:dev Creates a new migration file from schema diff + applies it + regenerates Prisma client After every change to schema.prisma Dev only
2 pnpm db:generate Regenerates Prisma client from current schema — does NOT touch the DB After pulling a branch with new migrations but no new schema changes Dev
3 pnpm db:seed Runs src/seed.ts — inserts test data After a fresh migration when you need data Dev
— pnpm db:studio Opens Prisma Studio at localhost:5555 Any time — visual DB browser Any
— pnpm db:migrate:deploy Applies all pending migrations silently, no prompts, no new files CI/CD pipeline before starting API. Never run locally against shared DB. Prod only

Direct package commands (same as root shortcuts)

pnpm --filter @shipflow/database prisma:migrate:dev     # = pnpm db:migrate:dev
pnpm --filter @shipflow/database prisma:generate        # = pnpm db:generate
pnpm --filter @shipflow/database prisma:migrate:deploy  # = pnpm db:migrate:deploy
pnpm --filter @shipflow/database prisma:seed            # = pnpm db:seed
pnpm --filter @shipflow/database prisma:studio          # = pnpm db:studio

⚡ Daily Development Workflow

Option A — Start everything (Turborepo)

pnpm dev

Turbo starts apps/api and apps/web in parallel with hot-reload.

Option B — Start services individually

# Terminal 1 — API (port 9000)
pnpm dev:api

# Terminal 2 — Web (port 9001)
pnpm dev:web
ServiceDev Command Inside PackageWhat it does
apps/api nest start --watch NestJS with hot-reload. Clears tsbuildinfo first to avoid stale incremental builds.
apps/web next dev --port 9001 Next.js App Router with HMR on port 9001.
packages/database tsc --watch Recompiles DB types on change. Run only when editing the database package itself.

Debug mode (API)

pnpm --filter @shipflow/api start:debug
# Attach Node.js debugger to port 9229

🏗️ Build (Production Artifacts)

Full build (all packages, correct order)

pnpm build

Turbo resolves the dependency graph automatically:

@shipflow/database  ──┐
                      ├──▶  @shipflow/api
@shipflow/shared    ──┘──▶  @shipflow/web

Individual builds

pnpm --filter @shipflow/database build   # prisma generate + tsc → dist/
pnpm --filter @shipflow/shared build     # tsc → dist/
pnpm --filter @shipflow/api build        # nest build → apps/api/dist/
pnpm --filter @shipflow/web build        # next build → apps/web/.next/

🌐 Running in Production

🔴 Production deploy order: build → db:migrate:deploy → start. Never run migrate:dev in production.

Step 1 — Set production env vars (apps/api)

apps/api/.env (production values)
NODE_ENV="production"
PORT=9000
DATABASE_URL="postgresql://user:pass@host:5432/ship_flow_prod?schema=public"
JWT_SECRET="<openssl rand -base64 64>"
FRONTEND_URL="https://your-production-domain.com"

Step 2 — Build

pnpm build

Step 3 — Apply pending migrations

pnpm db:migrate:deploy

Step 4 — Start the API

node apps/api/dist/main.js
# or via package script:
pnpm --filter @shipflow/api start:prod

Step 5 — Start the Web

pnpm --filter @shipflow/web start
# Serves the .next/ build — put behind a reverse proxy (nginx/Caddy) or deploy to Vercel

⚡ Quick Reference

Most Common Commands

# ── First time ───────────────────────────────────────────
pnpm install && pnpm db:migrate:dev && pnpm db:seed

# ── Every day ─────────────────────────────────────────────
